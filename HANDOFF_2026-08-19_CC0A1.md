# TheWorld handoff — CC0-A1 executed

**Date:** 2026-08-19  
**State:** first invalidation-sparsity census implemented and run. Positive opportunity receipt on simple encoded video; no runtime claim.

## What changed

`CC0-A` is now split into three stages:

```text
CC0-A1  validate the census/invalidation idea on an encoded temporal stream
CC0-A2  repeat it on a genuinely external/natural or task-real stream
CC0-B   only then learn cheap guards/routing and measure actual sparse runtime
```

This prevents a simple rendered asset from being silently promoted into the real architecture gate.

## New instrument

`experiments/cc0a_invalidation_census.py`

Dense oracle evaluates 11 receiver consequences every frame, while each receiver separately keeps its last accepted cached value. A receiver is marked invalid only when its consequence crosses its own tolerance from that cache.

The script reports raw frame change, ANY-receiver invalidation, per-receiver invalidation, receiver-slot invalidation fraction, invalidation matrix, correlations, equal-cost GLOBAL-OR/local opportunity ratio, and a tolerance sweep.

The oracle itself does not save work.

## Receipt

On the pre-existing 901-frame `world.mp4` rotating-globe asset, tolerance scale `0.35`:

```text
raw frame changed              100.00%
ANY receiver invalid            12.44%
receiver slots invalid/frame     1.202%
GLOBAL-OR / oracle-local work    10.35x
```

Across tolerance scales `0.15 -> 1.0`, the global-OR/local equal-cost ratio stayed:

```text
9.73x, 9.96x, 10.35x, 10.24x, 11.00x, 11.00x
```

A different sparse title-animation stream produced a smaller `2.68x -> 5.68x` range depending on tolerance. So the 10x ratio is not a hard-coded invariant of the script.

## Meaning

The opportunity predicted by Note 010 exists in this simple stream:

> the visual state can change continuously while most receiver-specific cached consequences remain valid.

The strong negative boundary remains:

> **This is not 10x faster inference.**

The dense oracle paid for every receiver. No guard, routing, memory traffic, candidate discovery, teacher refresh or wall-clock saving has been measured.
